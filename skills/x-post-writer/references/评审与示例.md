# 评审、改稿与示例

## 先查否决项

- **事实**：成绩、数据、时间、操作和截图是否有可用依据？有没有偷换范围、因果或确定性？
- **叙事与归属**：是否使用第一人称，亲历改写是否有用户授权，是否额外编了身份或成绩，是否给改写加原话引号？用户已要求“直接写成亲历”，就按素材执行，不退回旁观式摘要。
- **兑现**：开头承诺的方法、案例、结果或清单，正文是否真正交付？
- **平台**：是否误导、搬运、反复索取互动或承诺收益资格？按[X创作者规范](X创作者规范.md)核对。

任一失败先修订，不能靠情绪更强、标题更大或自评更高抵消。没可用数据就换方法、观察或有归属的案例，内部核验提示不进正文。

## 再按内容取舍

用“清楚 / 够用 / 需改”判断，并指向具体原句，不计算爆款概率。

| 维度 | 要问什么 | 常见修法 |
| --- | --- | --- |
| 对象 | 哪个读者在什么处境下关心 | 大行业词换具体任务 |
| 开头 | 问题、细节或感受是否有依据 | 删假反差、感叹和无依据数字 |
| 价值 | 带走哪一个判断、动作或解释 | 给完整小方法，少口号 |
| 动机 | 主驱动是否自然、符合账号目标 | 换入口，不靠夸张或羞辱 |
| 证据 | 哪个细节支持，适用于哪里 | 补真实过程，保留边界 |
| 形式 | 短推完整、长推推进、配文有补充吗 | 压缩重复，按语义分段 |
| 人声 | “我”是否有动作和判断，是否完成去AI味复核 | 保留具体表达，按诊断局部修改 |
| 标点 | 停顿、引语、问句与并列关系是否匹配 | 修含义和配对，不清空正常标点 |
| 后续 | 引来的人是否符合长期方向 | 回到目标读者，少无关刺激 |

拆对标先确定任务与真实看点，再分析开头、兑现、情绪和讨论入口。区分“文案中可观察的做法”和“仅凭文案无法证明的传播原因”，不承诺复制写法即可复制结果。

## 段落推进检查

完整长推逐段用一句话说明它给读者增加了什么；短推只查各句是否一起完成同一件事，无需套长表。底稿需要时记“段落位置 / 新信息或必要解释 / 依据 / 保留、合并或删减”。

- 新事实、具体动作、案例、概念区分、选择的后果，或回答读者疑问的解释，都可以推进内容；不要求每段新增数字或故事。
- 两段若只把“要具体”“要有价值”换词重说，合并；一段若回答“为什么这样做、这一步怎样完成、何时不适用”，即使没有新事实也可能必须保留。
- 让主要的人、事和动作尽早出现。把长定语和连续抽象名词拆开，指代接近对象；背景在理解动作需要时再交代，避免先堆整段行业概况。
- 检查解释与开头的关系：承诺步骤却只表达态度，补回材料中的步骤或缩小开头；承诺对照却只写一边，补足已知条件或换结构。
- 读出声检查句意和自然停顿；不以冒号、破折号、三项并列或某种句长自动否决。按[个人文风](个人文风.md)核对样文证据，再作局部修订。

例：“我开始重视截图。截图很重要。好的截图能提升教程质量。”三个判断没有说明截图干什么。

可改为：“我会把入口和容易点错的位置截出来，在旁边说明该看哪里。每一步再写清完成后该出现什么，读者才知道自己有没有做对。”动作与用途分别推进；具体界面和截图必须来自已有材料，未看过的界面不补造。

## 新手教程短推

输入是分享方法：“先说清读者、收获和可信依据，再让AI整理。”用户要求第一人称亲历式，不再输出面向全体读者的课堂摘要。

空泛写法：

> AI时代，掌握提示词就能轻松做出爆款。

没有方法，效果承诺无依据，也掩盖作者素材与判断。

可用写法：

> 我给AI的第一样材料，通常不是提示词。
>
> 我会先讲清读者卡在哪里，再补上要完成的任务、做过的步骤。材料齐了，才让它理顺结构、删掉重复。
>
> 这篇到底有什么可写，我得先说明白。

主驱动懒惰：降低起步成本；辅助傲慢：保留实际判断。解释不属于正文。

## 视频配文

只有用户描述：“电梯扶手清理视频，能看到前后差异。”

“这个人在清理电梯扶手”重复画面。可换为：“我看这个清理过程时，更想知道前后到底差在哪。视频里能对着看，比一句‘清理干净了’直观得多。”如果只收到描述，示例只是配文视角，助手不能在说明中声称已经观看视频。

借日常场景产生代入和好奇，不推断无法证明的细菌数量、疾病风险或清洁效果。没有画面细节，不自行描绘污物、工具和操作。

## 长推兑现与拆短

素材只支持“从新手问题提炼教程”，就不要承诺稳定涨粉公式。可以承诺：“把刚解决的问题，整理成别人能跟着做的教程。”正文展开任务、步骤、图位与卡点。

拆短可分别讲：怎样找新手问题、截图解释什么、如何检查标题承诺。每条补足背景，不用三个同义句冒充三个选题。

## 素材少或有矛盾

保留能成立的内容，缩小承诺和篇幅。可用问题清单或有归属的分析，不拼凑假案例满足长度。缺失信息决定主要结论时，先问一个关键问题。

用户无个人样文时，按已知偏好完成稿件；不声称已建立文风档案。只有一篇短推时，观察只适用于这次短推，不扩展为长文习惯。用户本次要求与旧文风不同，按当前要求调整，同时保留事实和归属。

## 交稿前的去AI味复核

必须按[去AI味检测](去AI味检测.md)保存初稿、扫描、语义复核并在修订后复测。以下是编辑示例，不是脚本自动改写或真实A/B传播实验。

初稿：“我认为，核心是：真正好的教程不是面面俱到，而是具体可用。综上所述，大家都值得收藏。”

修订：“我写教程时，会把题目缩到一个具体任务。入口在哪、哪一步容易卡住、怎样确认完成，我都会写清。”

修改理由：直接给动作，删空泛宣告及索取互动；保留正常逗号、顿号、问句内容和具体方法。不能只因出现“不是…而是…”就判原句由AI生成；若在准确区分两个概念，仍可保留。

对照检查：是否仍表达原判断，是否补了无素材事实，是否改变承诺范围。初稿本身不含具体方法而修订加入步骤时，这属于依据材料的补写，记录为内容改进，不假称纯语言替换。

## 输出形态

用“短推A / 短推B / 长推”等在正文外区分版本。策划说明仅在需要时写受众、主驱动、依据与推荐理由。不把“钩子、七宗罪、CTA、评分、待核实”等内部标签写进成稿；用户主题本来就在讨论这些概念时正常使用。
