# 去AI味：原版脚本、语义复核与复测

v1.2实际调用用户指定的[lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)原版程序。随包保留未修改的[detect.py](../vendor/lieflat-less-ai-tone/scripts/detect.py)、[report.py](../vendor/lieflat-less-ai-tone/scripts/report.py)、[语义判据](../vendor/lieflat-less-ai-tone/references/semantic-criteria.md)及[许可证](../vendor/lieflat-less-ai-tone/LICENSE)。固定版本与逐文件哈希见[来源清单](../vendor/lieflat-less-ai-tone/UPSTREAM.json)；作者shiujan，CC BY-NC 4.0，商用另按原许可办理，不把用户允许运行视为额外商用授权。

目标是改善表达，不鉴定AI来源、不出AI概率、不保证平台准入。原版输出中的研究参照由上游作者提供，不代表本次稿件完成统计显著性检验。

## 输入与运行

只检查待发正文。短推逐条保存，长推保存完整稿件；策划标签、来源说明、版本名不混入统计。输入须为UTF-8，本地适配器严格校验，建立统一LF、去BOM的快照，原文件不改。输出目录必须是新路径，失败时保留记录，排查后使用新目录重跑，不静默覆盖。

从技能目录运行：

```text
python -B -X utf8 scripts/run_upstream.py scan 草稿.md --out-dir 检测前
```

适配器校验原版文件哈希，通过当前Python解释器执行原CLI，保存：

- `原仓库候选.json`：原版`detect.py --candidates`输出，含rename/cohesion/colon/iso3四类候选。
- `原仓库检测.json`及`原仓库检测.txt`：达到500汉字时运行原版常规检测；保留原始结构和分级。
- `补充表达扫描.json`：原v1.1的`tone_check.py`结果，补查强承诺、互动索取等；不能冒称原版结果。
- `输入稿.md`、`运行记录.json`：快照、原稿哈希、上游SHA、运行分支、实际候选与截断信息。

依赖仅Python标准库，不联网、不外发稿件、不自动更新。无Python或执行失败时，说明原脚本未运行，按清单人工检查；不能说已完成原版检测。

## 短推与长推的区别

原版常规CLI提示至少约500汉字，本适配器严格按500汉字选择分支，不利用原版四舍五入的边界差异。短推仍运行原版候选提取，并结合逐句阅读及补充检查；不生成虚假的常规统计JSON、不把多条无关稿拼起来凑长度。原候选也有最小段长，零候选不表示短推合格。

长推达到门槛时运行完整常规CLI及候选提取。保留A/B/C/H/X/F各层的原始输出，但不直接执行正则给出的所有改法。C类分布只作描述，X类不因其出现而删改，H类比喻保留并在有争议时交作者判断，F类标点按实际功能复核。正常问句、编号和标点不能机械删除。

## 四类语义逐条判断

读取随包[原版语义判据](../vendor/lieflat-less-ai-tone/references/semantic-criteria.md)，逐条按其封闭标签判断。执行者为当前会话模型，不需安装另一模型或连接外部语义服务。

在原候选副本中加`label`、`confidence`（高/中/低）、`reason`，保留原始条目、顺序、meta和阴性判读。判不准用原标签中的“无法判断”，不能把它改为无问题。另记录“修改 / 保留 / 误报 / 待作者判断”与理由，不能用这些编辑结论替代封闭语义标签。

候选截断时报告各类原始数量、实际覆盖数量及未覆盖范围；不声称全篇全部判完。语义模块只是取样段落/接口，可能跳过短段过渡；应指出这种上下文限制，不为消除“连环”故意制造逻辑跳跃。程序不核定经历、事实、版权或X收益资格，另按素材、叙事授权和[平台规范](X创作者规范.md)检查。

## 修改与复测

自己的新稿，或用户已授权优化的稿件，在当前任务内直接作必要的局部修改；沿用现有授权，不因上游文档另有确认流程而重复询问。用户仅要求检测时只给诊断，不覆盖原稿。最多两轮针对性修改，不循环刷分。

每处修改指出原位置与理由，保留事实、条件、数字、判断强度、信息点和第一人称。没有问题就保留，不为“人味”添错字、假经历或随机断行。语义明确但没有安全改法时说明保留理由，不强求清零。

改稿另存，运行同样的scan命令到`检测后`；重新判断改后候选并对照改动是否完成、有无新问题。长稿可通过原版report.py生成报告：

```text
python -B -X utf8 scripts/run_upstream.py compare 检测前 检测后 --semantic 改前语义判读.json --out 去AI味对比.md
python -B -X utf8 scripts/run_upstream.py compare 检测前 检测后 --semantic 改前语义判读.json --format html --out 去AI味对比.html
```

适配器核对语义条目完整性、原始字段及标签，不替模型生成判读。报告使用的是改前语义文件；改后判读另外保留，不能据此声称report.py自动完成了双侧语义评测。没有传入语义文件时，只能称脚本指标对比。短稿没有常规统计时，用逐句前后对照，不调用常规指标报告冒充完整结果。

## 交付

公开推文只含成稿，报告留在正文外；用户需要时给原始输出、逐条判读和前后例句。可写清实际运行了哪个原脚本、哪些内容作了人工或模型复核。未命中、密度降低和第一人称都不证明真人来源、原创资格或收益合规。
