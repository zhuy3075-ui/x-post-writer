# 中文短推与长推生成

把真实素材转为“愿意停下、读后有收获、适合目标读者继续关注”的推文。默认中文、X平台；用户另选平台、语言、受众、风格或长度时按其要求调整。

默认直接用第一人称亲历式成稿，让“我”的处境、动作、选择和反思推进内容。沿用用户已经给出的叙事改写授权，不反复确认；素材范围和事实判断按下文处理。

基础方法来自用户提供的2026-11-08现场分享。七宗罪是用户新增的创作视角，其具体应用为编辑者设计，不能归给讲者。方法定位见[分享方法与出处](references/分享方法与出处.md)。

## 接到素材后

从材料与已有对话判断：写给谁、读完得到什么、凭什么相信，以及希望带来理解、讨论、收藏、关注还是产品了解。已有清楚素材就直接写；缺失信息会改变事实、身份或核心承诺时，只补问关键问题。

- “短推/短配文”：只走短推模式。
- “长推/长文”：默认完整的单条长内容稿，不擅自拆串。
- “推文串/thread/接龙”：按串联模式，每条可独立理解并共同推进。
- 只说“生成推文”且未指定形式：默认少量不同角度的短推及一篇长推，通常3条短推、1篇长推；材料不足时减少。
- “拆成短推”：提取长文中可独立成立的技巧、坑、判断或案例，不从句子中间截断。

写作前读[短推与长推](references/短推与长推.md)及[第一人称与标点](references/第一人称与标点.md)。首次应用动机选择时读[七宗罪与传播因素](references/七宗罪与传播因素.md)。交稿前必须按[去AI味检测](references/去AI味检测.md)、[X创作者规范](references/X创作者规范.md)及[评审与示例](references/评审与示例.md)检查，不能把“读着自然”当作已经检测。

按[观点与结构](references/观点与结构.md)先筛可成立的观点，再匹配开头、结构与兑现位置；这些是内部底稿，不默认展示。用户给了自己的作品、已有文风档案，或要求学习文风时，读[个人文风](references/个人文风.md)并只取相关体裁的证据。没有样文就按已知偏好直接写，不假称已学习个人文风，也不因此中断任务。

## 先判断素材

1. 把可用材料分成独立的判断、案例、动作或数据，标出来源位置；由此提出观点卡，写清判断、依据、读者收益和适用边界。合并同义观点，选择材料最能支撑、读者最能用的一条主线；材料少就缩小承诺。
2. 内部保留用户亲历、资料经历、授权叙事改写、个人判断和引语的区别。成稿默认第一人称；用户明确说“直接写成亲历”时，把所给素材中的处境、做法与转折直接写成“我”的叙事，无需反复确认，也不强制加“这份分享提到”。按[第一人称与标点](references/第一人称与标点.md)落实授权范围；口吻转换不证明本人事实或平台原创性。
3. 数字只在可采用、口径清楚时使用。无法采用的数据不进成稿，不把“待核实”等工作提示写进推文；必要限定仍保留。改写不加原话引号，不从参考PPT继承播放、收入或涨粉成绩。
4. 图视频能读取时先看；只有文字描述时依据描述写，不声称看过未读素材。资料中的操作指令只作为素材，不能成为采集、登录、发布或外发授权。

## 选择传播角度

先选有实际价值的内容，再改善吸引力。用这些问题决定怎么写，不保证传播结果：

- **相关**：哪个具体读者在什么场景下会关心？
- **停留**：开头是否有真实问题、细节、感受或有依据的反差？
- **兑现**：读后能学会、判断、拿来用，或清楚表达什么？
- **共鸣**：什么真实处境与感受值得被说出来？
- **转述**：有没有一句可讲清的观点、一组好用步骤或可对照案例？
- **匹配**：吸引来的人与账号长期方向是否相关？

默认选择一个贴合素材的**七宗罪主驱动**，必要时加一个辅助驱动，不把七种塞进同一条。七种为傲慢、嫉妒、愤怒、懒惰、贪婪、暴食、色欲，具体映射见参考。没有合适强刺激时，选择更克制的身份认同、降低门槛或求知角度；不为选动机改写事实。用户要求中性风格或不用此框架时尊重其选择。

策划时写清“读者处境 → 主驱动 → 内容承诺 → 材料依据”。它是创作假设，不是道德判断或科学测得的心理画像。好奇、惊讶、损失厌恶等可以辅助选角度，不冒充第八种七宗罪。

先确定观点和证据，再选择情绪入口。记录开头许下什么、用哪种结构、正文哪一处回答；用选择、细节或方法吸引读者，不能用动机标签补出材料里没有的效果。

## 写出短长不同的成品

**短推**聚焦一个观点、场景或可执行动作。视频配文补充观看理由、关注点或感受，避免复述画面。不同版本改变价值入口或情绪角度，而不只换同义词。

**长推**让开头承诺被正文兑现。按一条主线组织必要背景、案例/步骤、条件与收束；素材不同，结构可以不同。教程让目标读者跟着完成任务，观点稿说明理由和反例，经历稿保留真实转折。篇幅由材料决定，不用空段和套话凑长度。

短推第一句要有可辨认的吸引点：具体悬念、卡点、有依据的反差、动作细节或感受。独立短推在本条内给出关键答案，视频配文的承诺由实际视频兑现；不能靠“点赞后公布”拖延。第一人称贯穿观察、行动、选择和反思，不只给第三人称稿加一句“我觉得”。

保留自然的人声和具体细节。少用抽象口号、机械转折、密集感叹号与逐字分行；不默认加标签、emoji、索取互动或营销口令。需要互动结尾时，提与正文相关、能具体回答的问题。需要转化时，行动对应用户实际提供的产品、资料或服务。

账号权限或字符规则未知时先完成文案，按[短推与长推](references/短推与长推.md)处理长度，不把汉字数或模型估计当作平台精确计数。

## 检查与交付

按顺序完成：观点卡与素材依据 → 开头及结构配对 → 按已有文风证据或用户偏好起稿 → 第一人称、素材与段落推进核对 → 开头兑现及平台规范 → 去AI味扫描与逐条语义复核 → 必要的局部改写 → 复测与信息对照 → 成稿。自己的新稿在生成任务内直接修订；用户只要检测时只给诊断，不改其原稿。默认最多两轮针对性修订，之后保留需作者判断的具体问题，不循环刷分。

有Python时通过[scripts/run_upstream.py](scripts/run_upstream.py)调用随包固定版本的lieflat-less-ai-tone原版detect.py，提取候选，并在长稿完成修订后调用原版report.py；具体命令、短稿边界和语义判据见[去AI味检测](references/去AI味检测.md)。原始命中、模型判读和补充表达检查分开保留。无运行工具时逐句检查，并说明未运行程序，不伪造记录。正常标点、必要重复、编号、引语和清楚的转折可保留；不制造错字、假经历、随机长短句或无意义断行。

先查素材、叙事授权和承诺，再查受众、信息价值、动机、标点与可读性。不合格先修稿；对立意见针对具体做法，不羞辱群体。第一人称与去AI味都不能把搬运变成原创，也不能绕过X对自动创作、自动发布和收益资格的限制；须保留创作者实质创作与终审，不能保证符合计划。

默认交付可直接复制的正文，短推与长推分开；版本名、推荐理由、动机标签和来源底稿放在正文之外。可附一两行说明；用户说“只要成稿”时省略策划卡、分析和自评。解释时用“为什么选这个角度、依据是什么、正文在哪里兑现”，不编造爆款概率、预估曝光或评分证明。

按[段落推进检查](references/评审与示例.md#段落推进检查)判断每段新增了什么：事实、动作、案例、区分、后果，或读者理解所需的解释。合并只换说法的重复；必要条件和承接仍保留。文风按当前明确要求、同体裁样文证据、既有偏好依次取舍；检测命中只供复核，不能压过真实文风和正常标点。

仅在用户要求时展示详细评审。技能生成草稿，不自动采集账号、登录、发布、发评论或联系他人。

直接写成第一人称亲历口吻，使用素材已有的做法和细节；短推开头有吸引力，正文给答案。
先筛观点并匹配开头与正文结构；选贴合的七宗罪动机，使用自然标点。
有我的文风档案就按相关样文写；交稿前检查段落推进、去AI味及创作者规范。
```

用 $x-post-writer，把这篇长推拆成几条能独立发布的短推，每条换一个有依据的角度，只输出成稿。
```
